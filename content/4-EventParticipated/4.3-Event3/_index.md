# Event: "Fireside Chat with Dr. Werner"

### Event Overview

- **Event Name:** Fireside Chat with Dr. Werner (AWS CTO), with the AWS FCAJ HCM community  
- **Date:** 02/10/2026  
- **Role:** Attendee  
- **Format:** In-person talkshow  
- **Location:** 26th floor, Bitexco Financial Tower, District 1, Ho Chi Minh City  

The session was organized by the AWS FCAJ HCM community and announced on the program's channels. It was a rare chance for interns to hear a senior AWS technology leader speak first-hand about how Amazon builds systems, its engineering culture, and what young engineers need to prepare for in the AI era. The room was full, with interns, mentors and community members attending.

### Key Topics

#### Amazon's "Builder" Culture
- Everything starts from the customer: clearly write down the problem and the benefit for users before choosing technology
- Small teams fully own their services: "you build it, you run it", so the people who write the code also operate it
- Dare to experiment, but results must be measurable; when something is wrong, fix it quickly

#### Designing Simple, Resilient Systems
- Complex systems usually grow out of a simple system that works well; avoid designing for complexity from the start
- Design for failure: any component can break, so decouple the parts so that one failure does not bring down the whole system
- Observability is part of the design, not something added at the very end

#### Cost as an Architectural Requirement
- Cost should be considered from the design stage, just like security or performance
- Resources that run all the time without serving anyone are waste; prefer architectures that run on demand or on a schedule
- Measure cost per unit of value (for example, cost per prediction) to know whether a system is sustainable

#### AI and the Software Engineering Profession
- AI helps engineers work faster, but engineers remain responsible for correctness, security and quality
- Core skills matter more than ever: understanding the problem, asking the right questions, verifying results

### Key Takeaways

- **Start from users:** a product is more useful when it answers the questions users really need answered
- **Simple first, optimize later:** choose a good-enough, measurable solution, then improve it
- **Design for failure and for cost:** both belong in the very first design
- **A builder's responsibility:** use AI to speed up, but always verify the results yourself

### Personal Learnings

#### A Change in Mindset
- Before this talk, I thought an AI project should use the most complex model possible. Afterwards, I understood that a simple model evaluated honestly is worth more than a complex model that cannot prove its value
- I learned to see cost as a design criterion rather than a number checked after the system is built


### Event Experience

The session had a friendly, close atmosphere. I listened carefully and tried to note down the keywords Dr. Werner shared. What impressed me most was how the speaker described very simple principles applied consistently at enormous scale, showing that good engineering is about discipline, not complexity.
